# Speaker Stages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Stages tab under Emails shows, per approved speaker and per stage, whether they have had the stage's email, what is missing and what needs a follow-up, and lets admins manage stages, skip or add them per speaker, and send or mark the missing ones.

**Architecture:** Two new admin-written Firestore documents (`meta/stages`, `speakerStages/{speakerKey}`) loaded live by the existing `DataProvider`. One pure module (`web/src/lib/stages.ts`) works out every cell, row, count and header from data the app already loads (cards, reviews, emails, threads); the grid, counts and filters all read from it. Sending reuses the existing send flow, which learns to arrive with several speakers ticked.

**Tech Stack:** React 19 + Vite + TS, React Router, Firestore web SDK, Vitest (`renderToStaticMarkup` for component checks), Firestore rules + `@firebase/rules-unit-testing`.

**Spec:** `docs/superpowers/specs/2026-11-24-stages-design.md` (binding, including "Calls made after the builder check"). Approved mockups: `docs/mockups/2026-11-24-stages/stages.html`, `manage.html`, `stages.css`, `stages.js`.

## Global Constraints

- Web code may import from `functions/src` only `model.ts`, `talkKey.ts`, `shared/*` and `email/fillIns.ts` (plus `email/recipients.ts`, already shared by the send flow). The stage logic lives in `web/src/lib/stages.ts`; nothing on the server computes stages.
- Never `dangerouslySetInnerHTML`. All copy renders as React text.
- Members read `meta/stages` and `speakerStages/*`; only admins write them. Members never see Send / Mark / Skip / Add / Manage controls (spec call 7).
- Template `stageId` stays unused and null; `meta/stages` is the only source of truth (spec call 1).
- `templateIds[0]` is the template a stage sends; later entries are templates it used before. Swapping a stage's template never drops an id.
- "Today" is the Istanbul date (`istanbulDate(now)` from `web/src/lib/send.ts`), with `now` from `useNow()`. A stage is due on and after `dueFrom`.
- Copy comes from the mockups: chips `Sent 4 Nov`, `Marked sent 3 Nov`, `Replied`, `Replied – needs an answer`, `Bounced`, `Problem`, `Scheduled 2 Dec`, `Sending`, `Missing`, `Due 1 Dec`, `Skipped`; filters `All` / `Missing` / `Needs follow-up`; header `Send to the {n} missing`, `Only speakers added`, `Template deleted`; menu `Send {stage}`, `Mark as already sent`, `Skip for this speaker`.
- Styling: existing tokens and chips only (`.mstate`, `.mstate.warn` for Missing and follow-ups, `.mstate.strong` Replied, `.mstate.line` Scheduled/Sending, `.faint` Due/Skipped). Port `docs/mockups/2026-11-24-stages/stages.css` into `web/src/styles.css`; no new colours. Grid scrolls horizontally with a sticky speaker column.
- No Claude co-author trailer in commits.
- Rules and emulator suites need Java 21 on `PATH`. Tests use fake data only (`example.com` addresses).
- Commands: web unit tests `npm test --prefix web -- <file>`; web types `npx tsc -b` in `web/`; build `npm run build --prefix web`; lint `npm run lint --prefix web`; rules `npm test` at the repo root; functions types `npx tsc --noEmit -p functions`.

## Review Focus

1. **Swapping a stage's template** must keep that stage's past sends counted (anti-goal 3). Task 2 `oldTemplateCounts`; Task 5 `withTemplateKeepsHistory`.
2. **"Mark as already sent" for a speaker the template refuses**: the server's `markEmailed` silently creates nothing (`created: 0`). The grid must say so, not show success. Task 6 `markNoteRefused`.
3. **"Send to the N missing" when some of them can't get the template** (refused, or already in flight): they must show on the send flow with their reason, not vanish. Task 6 `pickedNotReadyListsRefused`.
4. **A CC'd co-speaker on an email that bounced or failed**: the bounce belongs to the main recipient; the co-speaker must not be flagged, and a CC'd successful send must count for them. Task 2 `ccSuccessCounts`, `ccProblemIgnored`.
5. **A browser outside Turkey around midnight**: "due" must flip at 00:00 Istanbul, not local midnight. Task 2 `dueFlipsAtIstanbulMidnight`.

  ```ts
  export type Exceptions = Pick<SpeakerStages, 'skipped' | 'added'>
  export function stageCell<E extends EmailDoc>(i: { stage: Stage; speakerKey: string; exceptions: Exceptions | undefined;
    emails: E[]; threads: ReadonlyMap<string, ThreadDoc>; today: string }): Cell<E>
  export interface StageRow<E extends EmailDoc = EmailDoc> { g: SpeakerGroup; noApproved: boolean; cells: Record<string, Cell<E>> }
  export function stageRows<E extends EmailDoc>(i: { stages: Stage[]; groups: SpeakerGroup[]; status: (talkId: string) => Status;
    emails: E[]; threads: ReadonlyMap<string, ThreadDoc>; exceptions: ReadonlyMap<string, Exceptions>; now: number }): StageRow<E>[]
  export const FOLLOW_KINDS: ReadonlySet<CellKind>  // bounced, problem, answer
  export const SENT_KINDS: ReadonlySet<CellKind>    // sent, manual, replied, answer
  export const rowMissing: (r: StageRow) => boolean
  export const rowFollow: (r: StageRow) => boolean
  export function sortRows<R extends StageRow>(rows: R[]): R[]
  export function stageCounts(rows: StageRow[], stageId: string): { sent: number; missing: number; follow: number }
  export function stageSummary(stage: Stage, c: { sent: number; missing: number }, today: string): string
  export function cellLabel(c: Cell): string
  export function cellTone(c: Cell): '' | 'strong' | 'warn' | 'line' | 'faint'
  export const dueLabel: (iso: string) => string // '2026-12-01' → '1 Dec'
  ```
- Rules the code must follow (spec "A cell" + calls 2–6):
  1. Skipped (stage id in `exceptions.skipped`) → `skipped`, even if an email exists. `appliesTo: 'added'` and id not in `exceptions.added` → `notFor`. Ids in exceptions that match no stage are ignored.
  2. Candidates: emails with `templateId` in `stage.templateIds`, `state !== 'cancelled'`, and either `speakerKey === speakerKey` (own) or the speaker's key in `cc` lowercased (CC'd). A CC'd email counts only when `state === 'sent' && !bounce`.
  3. Time of an email: `(sentAt ?? sendAt).toMillis()`. If any candidate has `state === 'sent' && !bounce`, the latest such decides; otherwise the latest candidate decides.
  4. Deciding email: `bounce` → `bounced`; `failed`/`unknown`/`held` → `problem`; `sent` with `threadId` whose thread `speakerWroteLast` → `answer`; `sent` whose thread has `lastReplyAt` → `replied`; `sent` + `manual` → `manual`; `sent` → `sent`; `scheduled` → `scheduled` (`at` = `sendAt`); `queued`/`sending` → `sending`.
  5. No candidate: `stage.dueFrom !== null && today >= stage.dueFrom` → `missing`; `dueFrom` set and later → `due`; else `blank`.
  6. Rows: every group with `decision(g, status) === 'approved'`, plus any group with a sent (`state === 'sent'`, manual included, bounce or not) email of rule `acceptance` and no approved talk (`noApproved: true`). `today = istanbulDate(now)`.
